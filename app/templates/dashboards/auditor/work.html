Dashboard / Audit Workpapers
Scope:
The audit workpapers document the testing procedures, evidence gathered, and analysis performed for the audit engagement of Anixo Bank. The focus of this audit includes adherence to RBI Prudential IRAC Norms for loan classification and provisioning, as well as compliance with RBI Cybersecurity Guidelines.

Loan Classification and NPA Provisioning Controls (RBI IRAC Norms)
Data Protection and Cybersecurity Controls (RBI Cybersecurity Guidelines)
Access Control and Authorization Mechanisms
Incident Response and Recovery Procedures
Third-Party Vendor Risk Management
Financial Reporting and Reconciliations

Objective:

Verify that Anixo Bank’s loan classification and provisioning practices are in line with RBI’s Prudential IRAC norms, ensuring accurate classification of NPAs and proper provisioning based on borrower repayment histories.

Test Procedures:

  • Sample Loan Selection: Select a representative sample of loans, including standard assets and NPAs.
  • Provisioning Calculation: Recalculate provisions for the sampled NPAs.
  • Review Documentation: Examine loan files for borrower repayment history, financial statements, and NPA recognition.

Key Documents:

  • Loan files and agreements
  • Borrower financial statements
  • Provisioning worksheets
  • NPA reports from the bank’s loan management system

Control Tests:

Control Description Test Description Control Questions Test Type Evidence Seen Test Results
Accurate classification of loans Reviewed loan classifications against RBI IRAC norms Are loans classified in the correct category? (Yes/No) Walkthrough and recalculation Loan reports, borrower statements 10% of sampled loans misclassified
Adequate provisioning for NPAs Recalculated provisions based on RBI requirements Is provisioning correctly calculated for NPAs? (Yes/No) Recalculation Bank provisioning worksheet 3 out of 50 provisions understated

Results:

  • 10% of the loans sampled were incorrectly classified, leading to inaccurate NPA reporting.
  • Under-provisioning observed in 3 loans out of the sample of 50, which may lead to inadequate financial reporting.

Objective:

Assess the effectiveness of Anixo Bank’s data protection controls, ensuring compliance with RBI’s cybersecurity guidelines, specifically focused on access control, encryption, and incident response.

Test Procedures:

  • Access Logs Review: Check access logs to ensure that only authorized personnel have access to sensitive financial systems.
  • Encryption Verification: Test encryption mechanisms for data at rest and data in transit.
  • Incident Simulation: Conduct a simulated cybersecurity breach to test the bank’s incident response.

Key Documents:

  • Access control logs
  • Encryption policies
  • Incident response plan
  • System access reports

Control Tests:

Control Description Test Description Control Questions Test Type Evidence Seen Test Results
Restrict access to sensitive data Review access logs for unauthorized access Are access controls in place for sensitive data? (Yes/No) System review Access logs 2 instances of unauthorized access
Data encryption for sensitive data Verify that encryption is in place for data at rest and in transit Is customer data encrypted as per guidelines? (Yes/No) Walkthrough Encryption policy, system logs Encryption policies were compliant
Timely response to incidents Test incident response via a simulated breach Is the incident response plan adequate? (Yes/No) Simulation Incident response logs Delays in escalation noted

Results:

  • Access Control Gaps: Two instances of unauthorized access were found where junior staff had access to critical financial data.
  • Incident Response: The response to the simulated breach was delayed, highlighting gaps in the incident escalation process.

Objective:

Evaluate the access control mechanisms and ensure that role-based access is enforced in line with the bank’s data protection policies and RBI cybersecurity requirements.

Test Procedures:

  • Role Review: Review user roles and permissions to ensure segregation of duties.
  • Authorization Logs: Check authorization mechanisms for high-value transactions.

Key Documents:

  • User access reports
  • Role-based access control (RBAC) policies
  • Transaction approval logs

Control Tests:

Control Description Test Description Control Questions Test Type Evidence Seen Test Results
Ensure proper segregation of duties Review user roles and permissions Are roles and duties properly segregated? (Yes/No) System review Access control logs, RBAC policies Duties for high-value transactions are not sufficiently segregated
Limit access to high-value transactions Review approval logs for high-value transactions Are only authorized personnel approving high-value transactions? (Yes/No) System review Transaction logs Access granted to unauthorized users

Results:

  • Lack of segregation of duties in critical financial transactions, increasing risk of fraud.
  • Instances where unauthorized users approved high-value transactions.

Objective:

Evaluate the bank’s incident response plan and its effectiveness in managing and recovering from cyber incidents.

Test Procedures:

  • Response Time Testing: Simulate a cybersecurity breach and measure response times.
  • Recovery Plan Review: Review the disaster recovery plan and test whether recovery objectives are met.

Key Documents:

  • Incident response plan
  • Disaster recovery plan
  • Incident logs

Control Tests:

Control Description Test Description Control Questions Test Type Evidence Seen Test Results
Effective incident response Test incident response times Did the bank respond within defined thresholds? (Yes/No) Simulation Incident logs Response delayed beyond acceptable thresholds
Recovery from incidents Test recovery time objectives (RTO) Were recovery objectives met? (Yes/No) Walkthrough Recovery logs 90% of critical systems met RTOs, delays in non-core systems

Results:

  • Delays in responding to simulated incidents, indicating a need for improvement in the incident escalation process.
  • Recovery time objectives met for most critical systems but delayed for non-core systems.

Objective:

Assess Anixo Bank’s third-party vendor management, focusing on the risk management processes in place to monitor vendor performance and ensure compliance with security policies.

Test Procedures:

  • Vendor Contracts Review: Review contracts for key third-party vendors to ensure that security obligations are clearly defined.
  • Vendor Risk Assessment: Evaluate the risk assessments conducted on third-party vendors.

Key Documents:

  • Vendor contracts
  • Vendor risk assessment reports
  • Performance monitoring logs

Control Tests:

Control Description Test Description Control Questions Test Type Evidence Seen Test Results
Ensure vendor compliance with security policies Review vendor contracts for security clauses Do vendor contracts include adequate security provisions? (Yes/No) Document review Vendor contracts Security provisions missing in 20% of contracts
Perform vendor risk assessments Review risk assessments for third-party vendors Are vendor risk assessments performed regularly? (Yes/No) Document review Vendor risk assessment reports Risk assessments not conducted for all vendors

Results:

  • Vendor contracts lack sufficient security provisions in 20% of cases.
  • Not all vendors have undergone regular risk assessments, leading to potential cybersecurity risks.

Objective:

Review the bank’s financial reporting processes and ensure that reconciliations are performed accurately and on a timely basis.

Test Procedures:

  • Reconciliation Review: Review reconciliations between sub-ledgers and the general ledger.
  • Financial Statement Verification: Verify the accuracy of financial statement balances.

Key Documents:

  • Financial statements
  • Reconciliation reports
  • General ledger reports

Control Tests:

Control Description Test Description Control Questions Test Type Evidence Seen Test Results
Perform accurate reconciliations Review reconciliation reports Are reconciliations performed regularly? (Yes/No) Document review Reconciliation reports Reconciliations delayed for some accounts
Ensure accurate financial reporting Verify financial statement balances Are the financial statement balances accurate? (Yes/No) Walkthrough Financial statements, GL reports No discrepancies identified

Results:

  • Delays in performing reconciliations for certain accounts, increasing financial reporting risks.
  • No significant discrepancies identified in financial statement balances.
