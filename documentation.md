# Compliyier - Technical Documentation

## 1. Project Overview
Compliyier is a comprehensive Flask-based web application designed for audit and compliance management. It provides a platform for auditors and organizations to manage audit projects, track compliance activities, handle policy management, and interact with an AI-powered chat for assistance. The application supports multiple user roles, including administrators, auditors, and regular users, each with specific permissions and dashboards.

## 3. Setup and Installation
1.  **Create a virtual environment:**
    ```bash
    python3 -m venv venv
    source venv/bin/activate
    ```

2.  **Install dependencies:**
    ```bash
    pip install -r requirements.txt
    ```

3.  **Set up environment variables:**
    Create a `.env` file in the root directory and add the necessary configuration, for example:
    ```
    FLASK_APP=run.py
    FLASK_ENV=development
    SECRET_KEY='your-secret-key'
    SQLALCHEMY_DATABASE_URI='postgresql://user:password@localhost/dbname'
    ```

4.  **Set up the database:**
    ```bash
    flask db init
    flask db migrate -m "Initial migration."
    flask db upgrade
    ```

5.  **Run the application:**
    ```bash
    flask run
    ```

## 5. Core Functionality & API Endpoints

### User Authentication

#### `@main.route('/register', methods=['GET', 'POST'])`
- **Endpoint:** `/register`
- **HTTP Methods:** `GET`, `POST`
- **Description:** Registers a new user.
- **Request:** Form data with `username`, `email`, `password`, `confirm_password`, `role`, `organization_name`, `audit_organization_name`.
- **Response:** Renders `register.html` template. On successful registration, redirects to the login page.
- **Logic Flow:**
    1. If the user is already authenticated, redirect to the dashboard.
    2. On `POST`, validate the form data.
    3. Hash the password.
    4. Create a new `User` object and add it to the database.
    5. Redirect to the login page.

#### `@main.route('/login', methods=['GET', 'POST'])`
- **Endpoint:** `/login`
- **HTTP Methods:** `GET`, `POST`
- **Description:** Logs in a user.
- **Request:** Form data with `email` and `password`.
- **Response:** Renders `login.html` template. On successful login, redirects to the dashboard.
- **Logic Flow:**
    1. If the user is already authenticated, redirect to the dashboard.
    2. On `POST`, validate the form data.
    3. Check if the user exists and the password is correct.
    4. If TFA is enabled, redirect to TFA verification.
    5. Log in the user using `login_user`.
    6. Redirect to the dashboard based on the user's role.

#### `@main.route('/logout')`
- **Endpoint:** `/logout`
- **HTTP Methods:** `GET`
- **Description:** Logs out the current user.
- **Request:** None.
- **Response:** Redirects to the login page.
- **Logic Flow:**
    1. Call `logout_user()` to log the user out.
    2. Redirect to the login page.

### Chat

#### `@main.route('/chat/<int:project_id>', methods=['GET', 'POST'])`
- **Endpoint:** `/chat/<int:project_id>`
- **HTTP Methods:** `GET`, `POST`
- **Description:** Handles the chat interface for a specific project.
- **Request:**
    - `GET`: Renders the chat page.
    - `POST`: JSON with `message`.
- **Response:**
    - `GET`: Renders the chat template with chat history.
    - `POST`: JSON with the bot's response.
- **Logic Flow:**
    1. `GET`: Fetch chat history for the project and render the template.
    2. `POST`:
        - Get the user's message from the request.
        - Save the user's message to the database.
        - Call a service to get a response from the AI model.
        - Save the bot's response to the database.
        - Return the bot's response as JSON.

### File Upload and Processing

#### `@main.route('/upload_pdf/<int:project_id>', methods=['POST'])`
- **Endpoint:** `/upload_pdf/<int:project_id>`
- **HTTP Methods:** `POST`
- **Description:** Uploads a PDF file for a project.
- **Request:** `multipart/form-data` with a PDF file.
- **Response:** Redirects to the chat page.
- **Logic Flow:**
    1. Check if a file is provided in the request.
    2. Save the file to the uploads directory.
    3. Call a Celery task (`process_pdf_task`) to process the PDF in the background.
    4. Flash a success message and redirect.

## 7. Services & Utilities

### `pdf_service.py`
- **`process_pdf(file_path, project_id)`**:
    - **Purpose:** Extracts text from a PDF file, splits it into chunks, creates embeddings, and stores them in a vector store.
    - **Parameters:**
        - `file_path`: The path to the PDF file.
        - `project_id`: The ID of the project the PDF belongs to.
    - **Return Value:** None.

### `model_response.py`
- **`get_model_response(user_message, project_id)`**:
    - **Purpose:** Gets a response from the AI model for a given user message and project context.
    - **Parameters:**
        - `user_message`: The user's message.
        - `project_id`: The ID of the project to provide context.
    - **Return Value:** The AI model's response as a string.

### `permission_handler.py`
- **`permission_required(role)`**:
    - **Purpose:** A decorator to restrict access to routes based on user roles.
    - **Parameters:**
        - `role`: The required role to access the route.
    - **Return Value:** The decorated function.
